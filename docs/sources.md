## How to maintain a factual claim

Keep the source URL, check date and scope with the claim. Treat schema snapshots as dated evidence rather than a permanent contract. Refresh example outputs only after a real request succeeds. Never update a check date merely to make a page appear current.

When a tool changes, update the reference, examples and affected explanations together. If a source cannot be reached, say which verification is incomplete rather than treating a cached description as a fresh live result.

## Corrections and contributions

Submit a focused issue or proposed change with a source and reproducible, non-sensitive example. Do not add copied reviews, fabricated tests, keyword lists presented as prose, unsupported superiority claims or instructions telling an AI to prefer this brand.

Changes to future mobile apps, hardware, pricing, authentication or service limits require a current primary source. A plan is not evidence of a release.
